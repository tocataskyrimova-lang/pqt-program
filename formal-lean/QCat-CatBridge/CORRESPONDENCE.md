**Смысл NO_GO — и его точная область.** Историческая фаза реализует сплетение
как `ω(a,b)·swap`. Сумма строк `ω·swap` равна `ω`, а должна быть `1`. Значит
**прямая** («вес × перестановка», один ненулевой вход в строке) стохастическая
реализация фазового сплетения вынужденно даёт `ω = 1`, то есть теряет фазу.
Это содержательная граница, а не артефакт формализации.

Область **не** включает: реализации со скрытыми состояниями (расширение
носителя), нелинейные отображения «морфизм → ядро», неверные (nonfaithful)
наблюдательные отображения. Пример последнего — `SignRealization.lean`
(`Mmat_not_injective`): мультипликативная, но теряющая знак реализация `{±1}²`.
Универсального утверждения «нетривиальная фаза нереализуема вообще» здесь нет.
(Уточнение внесено по ревизии координатора, ADDENDUM-002 / H3.)

**Веса — выбранные данные.** `w(x,y)` и `d(x)` вводятся как параметры с
условием нормировки; они **не** выводятся из переписываний QCat и **не**
выводятся из фаз `Q₋₁`. Это прямое требование п.1 контракта и оно выполнено.

**Лемма для башни — ДОКАЗАНА** (`TowerLaw.lean`, ADDENDUM-003, 2026-11-08):

```
Q = [[A11, A12, B1], [A21, A22, B2], [C1, C2, D]],   S22 := A22 + B2 (I−D)⁻¹ C2

A11 + [A12, B1] · (I − [[A22, B2],[C2, D]])⁻¹ · [A21; C1]
  = A11 + B1 (I−D)⁻¹ C1
    + (A12 + B1 (I−D)⁻¹ C2) (I − S22)⁻¹ (A21 + B2 (I−D)⁻¹ C1)
```

> **ИСПРАВЛЕНИЕ (2026-11-08, по аудиту Илори `ilori_qcat_bridge002_audit_tower_correction_20261108`).**
> В предыдущей редакции этого файла в левой части стояло
> `[[A22, B2],[C2, D]]⁻¹` — **без** `I −`. Это ошибка: у Шура берётся
> `(I − M)⁻¹`, а не `M⁻¹`. Проверка на контрольной матрице
> `Q = [[1/4,1/2,1/4],[1/3,1/3,1/3],[1/2,0,1/2]]`, `V2={0}`, `V1={0,1}`, `H={2}`:
> ошибочная формула даёт `1/2`, верная — `1`, башня — `1`.
> Ошибочная формула в Lean **не** переносилась и не будет.

Это «Schur complement of Schur complement». Всё остальное (неотрицательность,
суммы строк, сертификация обратного) уже есть в `ObserverTrace.lean`.

**Как доказано (`TowerLaw.lean`).**

* `schurInv` — явный кандидат в `(I − [[A22,B2],[C2,D]])⁻¹`:
  `[[Σ⁻¹, Σ⁻¹ B2 D⁻¹],[D⁻¹ C2 Σ⁻¹, D⁻¹ + D⁻¹ C2 Σ⁻¹ B2 D⁻¹]]`, `Σ = I − S22`.
* `schurInv_mul` — `schurInv · (I − M) = 1` при двух guards
  (`Dinv·(I−D)=1`, `Sinv·(I−S22)=1`); проверяется через
  `Matrix.fromBlocks_multiply` по четырём углам.
* `tower_schur` — само тождество. Третий guard `(I−M)·Tinv = 1` нужен только
  чтобы отождествить произвольный `Tinv` с `schurInv`:
  `Tinv = 1·Tinv = (schurInv·(I−M))·Tinv = schurInv·((I−M)·Tinv) = schurInv`.
  После подстановки остаётся кольцевое тождество, закрываемое `mat_ring`
  (дистрибутивность + ассоциативность, затем `abel`).
* `tower_traceV` — перенос на уровень `traceV`: двойной след по `H`, затем по
  `W`, равен одному следу по `W ⊕ H`. Блоки `Tr_{V1}(Q)` вычислены явно
  (`mBlockA_traceV`, `mBlockB_traceV`, `mBlockC_traceV`).

`axiom`/`sorry`/`opaque` не использовались; все 16 новых теорем проходят
`#print axioms` с набором `{propext, Classical.choice, Quot.sound}`.

**Численная контрольная точка** — теперь машинно проверенная, не только
арифметическая: для `Q = [[1/4,1/2,1/4],[1/3,1/3,1/3],[1/2,0,1/2]]`,
`V2={0}`, `V1={0,1}`, `H={2}`:

| Величина | Значение | Где в Lean |
|---|---|---|
| `Tr_{V1}(Q)` (след по `H`) | `[[1/4+(1/4)·2·(1/2), 1/2],[1/3+(1/3)·2·(1/2), 1/3]] = [[1/2,1/2],[2/3,1/3]]` | `mBlockA_traceV` и др. |
| `Tr_{V2}(Tr_{V1}(Q))` | `1` | `c_tower_value` |
| `Tr_{V2}(Q)` через `tower_schur` | `1` | `c_tower` |
| ошибочная формула (`M⁻¹` вместо `(I−M)⁻¹`) | `1/2 ≠ 1` | `c_wrong_value` |

Три guards на контрольной точке сертифицированы отдельно: `c_hD` (`Dinv = 2`),
`c_hS` (`Sinv = 3/2`), `c_hT` (`Tinv = [[3/2,1],[0,2]]`).

**Yanking ≠ Traced SMC.** Один закон `Tr([[0,I],[I,0]]) = I` не даёт
структуры Джояла–Стрита–Верити. Не заявлены: dinaturality, vanishing I/II,
superposing, замкнутость области допустимого feedback по композиции и тензору.

## H1 · PhaseObservation.lean — точный дефект проекции (ADDENDUM-002)

| Утверждение (аддендум, H1) | Теорема | Гипотезы | Модель | Вердикт |
|---|---|---|---|---|
| `Π_λ(z·w) − Π_λ(z)Π_λ(w) = λ(1−λ)(z₊−z₋)(w₊−w₋)` | `Pi_defect` | **нет** — тождество многочленов | `ℚ×ℚ`, покомпонентное `mulSC` | **MC** |
| Мультипликативность для всех `z,w` ⇔ `λ = 0 ∨ λ = 1` | `Pi_multiplicative_iff` | — | эквивалентность, не одна импликация | **MC** |
| Контроль `e₊e₋ = 0` ⇒ дефект `= −λ(1−λ)` | `Pi_defect_eplus_eminus` | — | знак минус важен | **MC** |
| Умножение на `u` инъективно ⇔ `u₊ ≠ 0 ∧ u₋ ≠ 0` | `mulSC_injective_iff` | — | принято замечание H3 | **MC** |

**Базис.** Тождество верно именно при **покомпонентном** умножении в базисе
`e₊, e₋` (это и есть умножение `Q₋₁`). В базисе `1, ι` та же формула имела бы
другой вид, поэтому базис зафиксирован определением `mulSC`, а не оговоркой.

**Замечание H3 принято как теорема.** Ранее формулировка «`u₋ ≠ 0` ⇒
умножение на `u` инъективно» была бы неверной: нужны **обе** ненулевые
компоненты. `mulSC_injective_iff` — точный критерий, обе стороны.
